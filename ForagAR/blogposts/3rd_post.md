Our third lab session didn’t get off to the smoothest start. Alex and Salomeea had run into several problems with the application while working on their tasks for this session, and had found themselves stuck and unable to move forward without discussing it with the team. As a result, most of the session ended up being about figuring out solutions rather than working on something new.
The first issue was about the Unity version. Both Salomeea and Alex had received warnings from Unity indicating that the project was running on a different version than the one installed on their machines, and that it needed to be updated. Alex tried updating and found that it caused extensive changes across the project, which made them hesitate to commit them. There was some discussion about this over text before the session, but nobody wanted to be the one to make a change that could potentially break or compromise the work we had already done. We decided to leave it and discuss it at the meeting, even though it meant that Alex couldn’t complete their task for the session. After discussing it, we agreed that staying on different versions would only cause more problems, and that the best option was to update so that everyone would be working in the same environment going forward. Alex then committed the changes.
The second issue came up when Salomeea tried to push some of the mushroom models to our repository. Several of the files were too large for GitHub to accept, which meant she couldn’t push them despite having completed her task. We all took some time to research possible solutions and eventually decided to handle all of our models with Git LFS (Large File Storage). Git LFS works by storing large files separately and keeping only a reference to them in the repository itself, which keeps the repository small and avoids GitHub's file size limits. The problem with this solution, however, was that Git LFS only tracks files that are added after it has been activated. As a result, the models Salomeea had already added weren’t covered, and she had to redo her part of the work.
Looking back on the session, both problems came from the same place. When we set up the project in the first session, we focused on getting started quickly and didn’t agree on the setup around it, like checking if we had the same version of Unity and how we would handle large files like 3D models. Neither of the problems were particularly difficult to solve on their own, but they ended up holding back the progress of the whole team for a week. Going forward, we want to agree on these things before starting new work, and to bring up problems in the group chat as soon as they appear rather than waiting for the next session.
Even though this session was mostly spent on problem solving, it still moved the project forward. With the version update and Git LFS aet up, the whole team is now working in the same environment, and our repository is ready to hold the larger collection of mushroom models we are planning to add.
We used the remaining time to discuss our next steps and divide the work. Alex and Salomeea will return to the tasks from last session, with Alex focusing on the user interface and Salomeea redoing the import of the mushroom models. Angela will search for models of other plants that we can use for the plant section of the application, while Kriszti will research additional mushroom species to expand the content we can include. Finally, Alex will also be responsible for writing the devblog for this session.
